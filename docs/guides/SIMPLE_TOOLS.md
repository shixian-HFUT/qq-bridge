# 可选工具简写：`pi.simpleTools`（实验性）

本页说明一个**默认关闭**的实验性开关：让 Pi 后端把 QQ 工具改用短名字和自然文字参数，会话 key、令牌与已读水位改由桥接按当轮可信上下文自动绑定。

它解决的是一个具体的失败形态：模型要在参数里手写会话 key、令牌和已读水位，漏传或传错时这一轮就不会发到 QQ，而且从 QQ 侧看只是"没反应"。简写把这些字段从模型可见的参数里移走，但**不放松**任何执行期校验。

> 实验性：默认关闭，改动集中在工具名与参数形状。是否适合你的模型与负载，请在本机实测后再决定；本页不承诺"每条消息都会回"或"全面更稳定"。

## 适用范围

- 只影响 **Pi 后端**（`runtime.backend: "pi"`）。DSH 后端的请求体、工具面与提示文案完全不变（回归里断言了这一点）。
- 只影响**模型看到的工具清单与参数绑定**。默认模型、角色、白名单、权限与发送策略都不变。
- 在 Pi 后端下，只要开关打开，所有**非学习**会话的投递都会尝试按会话状态构造可信上下文（会话暂时没有令牌时不构造），工具名与参数随之简化；这包括 `chat`、`reserved`、`reserved2` 三种模式的会话。
- 但"简写说明"和"格式纠正"只发生在二代仿真（`reserved2`）的**普通唤醒回合**（内部记为 `chat-wake`）：
  - `chat` / `reserved` 仍按既有规则把回复文本自动转发到 QQ，不会被纠正成额外的发送工具调用；
  - 摘要投喂（`silent`）与其它系统提示（`internal`）既不追加简写说明，也从不纠正；
  - 学习/黑话回合保留原有行为：只有只读搜索工具、没有简写、没有绑定、没有纠正。
- 主要受益的是"一切皆工具"的二代仿真回合：文字必须经发送工具才会到 QQ。

## 启用与关闭

`config.json`（不是完整配置，只列出相关字段）：

```json
{
  "runtime": { "backend": "pi" },
  "pi": { "simpleTools": true }
}
```

- 开关只认布尔 `true`。字符串 `"true"`、数字 `1` 都**不**生效，与关闭等价。
- 缺省或 `false`：工具清单、参数、回合结束判定、纠正逻辑全部沿用旧行为（回归断言了关闭时工具 schema 原样透传、短名不出现；关闭时也不会新增纠正预算字段或改写工具调用记录）。
- 改开关需要重启桥接（配置在启动时读取）。
- 仓库里的 `config.example.json` 用 `false`，即模板默认关闭。

回滚：把 `pi.simpleTools` 改回 `false`（或删掉字段）并重启。历史 `mcp__snowluma__*` 长名工具一直可用，所以单个会话不必立刻迁移写法；开关本身是进程级设置，切换仍需重启。

## 工具面变化

同一个底层工具会同时以三种名字暴露，方便旧预设与旧会话继续工作：

| 短名 | 底层工具 | 参数变化 |
| --- | --- | --- |
| `send` | `qq_send_message` | `text`（字符串=一条，字符串数组=多条）、`reply_to`、`at`；key/token/水位自动绑定 |
| `read` | `qq_get_unread_messages` | `afterSeq` / `limit` |
| `recent` | `qq_get_recent_messages` | `limit` / `offset` |
| `mark_read` | `qq_mark_read` | 无参数；水位由程序绑定 |
| `wait` | `qq_wait_for_messages` | `purpose` / `timeoutMs` / `minNewMessages` / `quietMs` |
| `wake` | `qq_set_wake_config` | `config` 对象；水位由程序绑定 |
| `role` | `qq_get_prompt` | 无参数 |
| `state` | `qq_social_state` | 无参数 |

规则：

- 只映射**清单里真实存在**、且带会话 `key` 参数的 snowluma 工具。清单里没有的工具不会凭空出现。
- 名称解析是**精确表**：不做前缀、包含、大小写或模糊匹配。拼错的名称照旧得到"工具未找到"，不会被改写成任何有副作用的调用。
- 名称冲突时保留已有工具、不覆盖、也不为该目标新增短名。
- 其它 snowluma 工具（图片、语音、表情、记忆…）保留自己的名字和专属参数，只去掉 `key` / `token` / `throughSeq` 这类运行时能绑定的字段；非 snowluma 工具（联网搜索、宿主状态等）原样保留，参数一个不改。
- 历史长名入口（`mcp__snowluma__qq_*`）用宽松参数表接收调用，真正形状仍由 MCP 层 schema 校验；它只是兼容入口，不额外放松任何校验。

## 可信上下文与失败关闭

绑定来源只能是桥接自己的会话状态：

| 字段 | 来源 |
| --- | --- |
| 会话 key | 本次投递的目标会话（建会话时已校验模式与白名单） |
| 令牌 | 该会话当前的 agentToken；每次投递重新读取 |
| 已读水位 | 本次真正展示给模型的快照水位；没有快照时退回"已展示过的最大水位" |
| 原消息 ID | 快照里最后一条非自己发的消息（仅用于缺省时补 `requestId`） |
| 回合种类 | `chat-wake`（普通聊天唤醒）/ `silent`（摘要投喂）/ `internal`（其它系统提示） |

- 模型传的 `key` / `token` / `throughSeq` / `requestId` 一律**丢弃后重填**，不是填空：跨会话、伪造令牌、超前水位都过不去。
- 上下文缺失或非法时**失败关闭**：工具面仍然是简化的，但调用会被拒绝并返回明确错误，不回退到模型给的 key。
- 令牌的可见范围（按实际情况写，别当成全局承诺）：
  - 本上下文对象只作为桥接→Pi 的**内存参数**传递，它本身不会被写进提示正文、日志或会话存档（会话存档只持久化消息、记录与纠正预算，队列不落盘）。
  - **但既有二代唤醒提示本来就会把会话令牌展示给模型**（`buildWakePromptV2` 的「会话令牌」行，供历史长名调用手填）。开启简写后模型不必再抄它，旧提示文案不因此改变，所以不要据此认为"提示里从不会出现令牌"。
  - 开启简写后，工具调用记录里的 `key` / `token` 会脱敏成 `***`（关闭时保持旧存档行为），避免模型硬塞的令牌被写进审计存档。
- 执行期校验全部保留：白名单、会话有效性、令牌轮换、发送限流、结果去重仍由桥接逐次校验。简写只是少让模型抄字段，不构成任何授权。

## 成本：工具表与额外请求

- **工具表输入开销**：每轮请求都携带工具 schema。简化模式下每个可适配的工具会同时出现长名、裸 `qq_*` 名和短名，名字与描述变短、schema 变窄，但**条目数变多**。净效果取决于你启用了多少工具，可能略省也可能略贵，请按自己的工具集实测，不要默认更省。
- **有界格式纠正**：仅在普通聊天唤醒回合、模型只输出了文字且本轮没有调用过任何动作工具、也没有工具报错时，追加**一次纠正提示**。约束：
  - 每轮最多纠正一次；
  - 同一来源事件最多连续 2 次，之后暂停；新的真实 @ 或新消息会重新获得一次机会；成功执行动作后计数清零；
  - 内部回合（`silent` / `internal`）从不纠正，避免把摘要或后台提醒纠正成"去 QQ 发言"；
  - 剩余调用预算不足时不纠正。
- **纠正不等于只多一次请求**：纠正本身只追加一条提示（一次 follow-up 消息），但模型收到提示后可能继续调用工具、再产生后续模型/工具往返，总次数仍受 `pi.maxCallsPerTurn`（默认 12）约束。因此开启后单条消息的 provider 请求数**可能增加，增加多少不固定**，不能理解为"最多只多 1 次"。
- 不新增任何服务，也不为每条消息增加固定模型调用。

## 已知边界

- 纠正只是多给一次机会，**不能保证每条消息都有回复**：模型仍可能选择沉默、连续只输出文字，或工具本身失败。
- 结果不明或失败的发送不会由本纠正路径重试；避免重复发消息优先于"补一句"。
- 模型返回的损坏工具调用 JSON 不会被自动修复后执行：解析失败就是失败，不做宽松猜测；也不会把模型输出的内部文字直接发到 QQ，发言仍必须经过发送工具。
- 会话存档里会多出 `simpleCorrections`（纠正预算来源与计数）。关闭开关后旧逻辑不读它，保留该字段、会话和聊天历史即可。

## 离线验证

```sh
npm run test:simple-tools
```

等价于依次运行：

```sh
node scripts/test-simple-tools.mjs        # 纯函数：别名表、schema 裁剪、参数绑定、纠正判定
node scripts/test-simple-tools-bridge.mjs # 桥接接线：开关/后端/轮次种类/令牌轮换
node scripts/test-pi-simple-tools.mjs     # 真实 Pi SDK + 本地假 provider + 假执行器
```

三个脚本都不连接 QQ、不读生产配置、不调用真实模型，也不会写入生产状态。关闭开关的对照组、缺上下文的拒绝路径、未知工具名、发送失败/结果不明、内部回合不纠正都在回归里钉住。
